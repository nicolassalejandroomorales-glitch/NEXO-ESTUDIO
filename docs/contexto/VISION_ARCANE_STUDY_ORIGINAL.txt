PROYECTO
NEXO STUDYAPP 1.0 — “Arcane Study”

Esta ejecución transforma la actual V14 de Nexo Estudio en la primera versión formal del producto:

NEXO STUDYAPP 1.0

A partir de esta entrega, el versionado público seguirá:
1.0 → 1.1 → 1.2 → 1.3 ... → 2.0 → 2.1...

No crear un proyecto paralelo ni rehacer Nexo desde cero.
Partir del código real de V14, conservar compatibilidad y datos, hacer backup restaurable antes de modificar nada y migrar de forma segura.

OBJETIVOS FUNDAMENTALES DEL PRODUCTO

Nexo tiene tres promesas que tienen prioridad sobre cualquier elemento decorativo:

1. Hacer que estudiar sea entretenido, dinámico y deseable.
2. Ser académicamente serio: el usuario debe poder aspirar a una evaluación universitaria exigente estudiando principalmente mediante Nexo, sin garantías artificiales de nota.
3. Reducir carga mental de organización: ayudar al usuario a decidir qué estudiar, cuándo, durante cuánto tiempo y por qué.

Regla rectora:
“El aprendizaje es el producto. El videojuego hace que quieras volver.”

La estética jamás puede sacrificar claridad, rendimiento, accesibilidad o rigor académico.

==================================================

- Baja

- Partículas bajas

Movimiento ambiental:
- Reducido
- Normal
- Rico

Mascota:
- Movimiento reducido
- Completo

AUTO MODE:

Considerar de forma segura:
- hardwareConcurrency;
- deviceMemory si existe;
- tamaño/resolución;
- reduced motion;
- rendimiento observado.

Siempre permitir override manual.

PARTÍCULAS:

Off:
0.

Low:
muy pocas, costo mínimo.

High:
más riqueza visual, pero con límites.

Nunca generar cientos de partículas DOM.

LIFECYCLE:

Si el usuario sale de Inicio y entra a Perfil:
Inicio NO debe seguir ejecutándose.

Al desmontar una habitación:
- cancelar RAF;
- cancelar timers;
- detener observers;
- detener animaciones;
- liberar listeners;
- pausar/destruir Rive no utilizado;
- descargar audio ambiental correspondiente;
- limpiar recursos;
- detener cualquier engine pesado.

No mantener habitaciones invisibles consumiendo CPU/GPU.

Pestaña en background:
pausar ambient animations.

Offscreen:
IntersectionObserver cuando corresponda.

Lazy load:
- rooms;
- course assets;
- Rive;
- RDKit/Ketcher;
- audio;
- juegos;
- assets pesados.

Phaser NO debe cargar en el Game Hub 1.0 si no hay juego activo.

PERFORMANCE BUDGET:

Objetivos:
- LCP < 2.5 s en dispositivo móvil medio bajo condiciones razonables.
- CLS < 0.1.
- INP objetivo < 200 ms.
- input nunca bloqueado por ambientación.
- transiciones principales 220–400 ms aproximadamente.
- respuesta visual inmediata al input.
- 55–60 FPS objetivo en equipos normales.
- degradación elegante en equipos modestos.
- nunca depender de 60 FPS para poder estudiar.

Crear ruta dev:
?nexoDev=1#/performance

Mostrar:
- FPS aproximados;
- room activa;
- animaciones activas;
- particles count;
- Rive instances;
- listeners/timers principales;
- assets cargados;
- modo gráfico;
- memoria cuando API disponible.

Añadir tests de lifecycle y memory leaks razonables.

5. Rey Mago

Estos rangos son POR CONCEPTO.

No son simplemente nivel global de cuenta.

VISUAL:

Cada concepto tiene Fuego Arcano.

Mago Principiante:
llamita muy pequeña.

Intermedio:
llama pequeña estable.

Avanzado:
fuego mediano.

Experto:
fuego grande con detalles arcanos.

Rey Mago:
gran fuego arcano distintivo/coronado.

El fuego debe ser legible también sin animación.

NO depender solo del color.
Añadir:
- nombre;
- icono;
- estado accesible.

CRITERIO:

NUNCA subir de rango por:
- terminar una lección;
- hacer clic;
- tiempo por sí solo;
- XP;
- repetir una pregunta fácil.

El rango depende de evidencia.

Dimensiones mínimas:

- autonomía;
- variedad;
- razonamiento/justificación;
- resolución en más de una familia;
- contexto nuevo;
- errores/misconceptions;
- prerequisitos;
- recuerdo diferido;
- tiempo activo mínimo.

TIEMPO ACTIVO:

Crear ActiveStudyTimer.

Cuenta exclusivamente en actividades académicas reales:
- lesson;
- practice;
- review;
- rescue;
- assessment-style;
- material actively used cuando corresponda.

NO contar:
- Home;
- Tienda;
- Perfil;
- menus;
- Game Hub;
- pestaña oculta.

Pausar si:
- document hidden;
- app background;
- sesión claramente inactiva durante periodo razonable.

No exigir clic constante durante lectura.
Diseñar temporizador sensible al contexto.

Cada concepto puede definir thresholds propios.

Fallback 1.0 aproximado configurable:

Principiante:
≥ 5 min activos
+ evidencia guiada/comprensión básica.

Intermedio:
≥ 12 min activos acumulados
+ evidencia independiente repetida.

Avanzado:
≥ 25 min activos
+ éxito independiente en ≥2 ProblemFamilies
+ alguna evidencia de explicación/justificación.

Experto:
≥ 40 min activos
+ rendimiento sólido en múltiples familias
+ desafío estilo evaluación o dificultad alta
+ contexto nuevo
+ sin debilidad crítica abierta.

Rey Mago:
≥ 60 min activos acumulados
+ distribuidos en múltiples sesiones
+ evidencia en días distintos
+ delayed recall/revisión posterior
+ rendimiento sin pistas
+ contexto nuevo
+ no misconception/prerequisito crítico sin resolver.

IMPORTANTE:
Estos thresholds NO deben quedar rígidos universalmente.
Permitir override por concepto/dificultad.
El Inspector debe poder mostrarlos.

FSRS decide CUÁNDO revisar.
Evidence/Knowledge Engine decide QUÉ sabe.
Tiempo solo agrega una barrera mínima.
